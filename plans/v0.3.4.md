# Plan v0.3.4 - Variable-Aware Textboxes

**Fractal**: TBD - to be determined before release finalization

## Overview
Version 0.3.4 upgrades the GUI textboxes to support project variables, enabling parametric fractal design and batch parameter sweeps.

## Dependencies
- **v0.3.3** - Project system with variable definitions
- **v0.3.0** - Job queue for batch rendering parameter sweeps

## Feature: Variable-Aware Input System

### User Experience

**Current:** Textboxes accept only literal numeric values.

**After:** Textboxes accept:
- Literal values: `256`, `-0.743`
- Variable references: `${base_iterations}`
- Expressions: `${base_iterations * 2}`
- Ranges (for sweeps): `${range(100, 1000, 100)}`

### Affected Input Fields

All numeric inputs should support variables:
- Center X/Y
- Zoom
- Max iterations
- Julia c_real/c_imag
- Mandelbrot power
- All fractal-specific parameters
- Export dimensions
- Export scale

### Implementation

#### Phase 1: Variable-Aware Input Widget
- [ ] Create `VariableTextBox` widget wrapper
- [ ] Accepts string input
- [ ] Parses as: literal, variable reference, or expression
- [ ] Shows resolved value next to input (e.g., `${base_iter}` → `256`)
- [ ] Visual indicator: different styling for variable vs literal

#### Phase 2: Expression Evaluation
- [ ] Reuse expression parser from v0.3.1/v0.3.3
- [ ] Evaluate expressions against project variable context
- [ ] Handle undefined variable gracefully (show error, use fallback)
- [ ] Re-evaluate when project variables change

#### Phase 3: Range Support for Sweeps
- [ ] Range syntax: `${range(start, end, step)}`
- [ ] When parameter contains range, enable "sweep mode"
- [ ] Sweep mode: render multiple frames, one per range value
- [ ] Integrate with job queue: each range value becomes a job
- [ ] Re-enable the deferred Julia Parameter Sweep animation UI once variable-backed sweep ranges can drive the existing animation interpolation cleanly

#### Phase 4: UI Polish
- [ ] Autocomplete for variable names
- [ ] Syntax highlighting: variables blue, operators black, errors red
- [ ] Tooltip showing evaluated result
- [ ] Error indicator if expression invalid

### Range Sweep Workflow

1. User enters range in parameter: `c_real = ${range(-1, 1, 0.1)}`
2. GUI shows: "Sweep mode: 21 values"
3. User clicks "Queue Sweep"
4. 21 jobs added to queue, each with different c_real value
5. Output files named: `fractal_c_real_-1.0.png`, `fractal_c_real_-0.9.png`, etc.

### Advanced: Multi-Parameter Sweeps

- [ ] Multiple range parameters = cartesian product
- [ ] Example: `c_real = range(-1, 1, 0.5)` + `c_imag = range(-1, 1, 0.5)` = 25 jobs
- [ ] Warn user about large sweep sizes
- [ ] Optional: random sampling instead of full grid

### Design Language

Establish consistent design patterns for variable-aware inputs:

```
+-------------------------------------------+
| Max Iterations: [${base_iter * 2}]  = 512 |
|                 ^^^^^^^^^^^^^^^^^   ^^^^^ |
|                 Input (blue)        Result |
+-------------------------------------------+
```

- Blue text indicates variable/expression
- Gray "= result" shows evaluated value
- Red border if expression invalid
- Dropdown arrow for variable autocomplete

### Integration Points

- **v0.3.0 Job Queue:** Sweeps generate multiple jobs
- **v0.3.3 Projects:** Variables come from project context
- **v0.2.1 GIF:** Range sweep over time = animation frames
- **Custom equations:** Can reference project variables
- **Julia Parameter Sweep animation** (deferred from v0.2.1): The `AnimationType::JuliaParamSweep` variant exists in `animation.rs` but is hidden from the GUI pending this variables/sweep system. Re-enable it here by wiring the sweep range into the animation interpolation.

### Performance Considerations

- Expression evaluation happens on each input change
- Should be fast enough for real-time preview updates
- Cache evaluated results, invalidate on variable change
- Batch updates: if user types quickly, debounce evaluation
