## Overview
Version 0.2.2 introduces a CPU high-precision rendering pipeline using fixed-width software floats at user-selectable bit widths, enabling zooms far beyond f64 limits. This is deliberately a CPU-only first pass; GPU adaptation of fixed-width deep precision is deferred to a future plan once the CPU implementation is well-understood. This release also completes the Insideout Dragon fractal (the release fractal) with proper numerical stability handling and hi-precision support.

Implementation order within this release:
1. CPU hi-precision pipeline on Mandelbrot (verification target)
2. Insideout Dragon stability fixes + integration
3. Insideout Dragon hi-precision support

## Insideout Dragon Implementation
**Status**: Deferred from v0.2.0 due to numerical stability concerns
**Formula**: z_{n+1} = z_n^2 + f(abs(z_n)) + j*g(abs(z_n))
- f(r) = r*((r-1)^2)(r^2-1)/((1+r^3)^2)
- g(r) = r*((r+1)^2)(r^2-1)/((1+r^3)^2)
- z_0 = 1/(x_0+j*y_0)

**Numerical Stability Requirements**:
- [x] Handle singularity at origin (z_0 = 1/(x+iy), undefined at x=y=0) — existing code has guards
- [x] Check for near-zero denominator in f/g functions ((1+r^3)^2 < epsilon) — existing code
- [x] Detect NaN/Inf in iteration loop (use is_finite() check) — existing code
- [x] Add divergence safety bailout (|z|^2 > 1e30) — existing code uses escape_radius param
- [x] Implement escape_radius parameter with GUI controls (default: 2.0) — existing FractalGUI impl

## Main Features

### CPU High-Precision Pipeline
**Priority**: High
**Status**: Planning

**Description**: A new orthogonal rendering mode using software floating-point at fixed user-selectable bit widths, enabling zooms beyond f64 precision limits. This is a separate setting from the CPU/GPU backend selector — users explicitly choose both the backend and the precision level.

**Library**: `astro-float` (pure Rust, MIT/Apache-2, no C deps, works on Windows out of box).
Alternative considered: `dashu` — also viable but `astro-float` is more focused on floating-point arithmetic.
Rejected: `rug` — wraps GMP (C library), LGPL license, painful Windows build.

**Precision Tiers** (powers of two, user-selectable via dropdown):
- 64-bit (f64 equivalent — baseline, useful for comparison)
- 128-bit
- 256-bit
- 512-bit
- 1024-bit

**UI Design**:
- Precision is a separate orthogonal control from the CPU/GPU backend radio buttons
- When "CPU Hi-Prec" is selected as the backend, a dropdown appears alongside it for bit width selection
- User sees immediate preview update on backend or precision change (same `needs_redraw` pattern)
- No automatic switching — user always makes the choice explicitly
- No guardrails on resolution or iteration count in this release

**RenderBackend enum extension**:
```rust
pub enum RenderBackend {
    Cpu,
    CpuHiPrec { bits: u32 },
    #[cfg(feature = "gpu")]
    Gpu,
}
```
`bits` is one of: 64, 128, 256, 512, 1024.

**Rendering pipeline integration**:
- `rendering_pipeline.rs` dispatches to a new `cpu_hiprec_backend` module when backend is `CpuHiPrec`
- The hi-prec backend implements the same pixel-iteration interface as the existing CPU backend
- Both preview (`RenderTarget::Preview`) and export (`RenderTarget::Export`) go through the same hi-prec path
- Rayon parallelism still applies — each pixel is independent, precision is per-thread

**Fractal trait integration**:
- Fractals that support hi-prec implement a separate `iterate_hiprec()` method (or a blanket default that returns an error/unsupported marker)
- `capability_table.md` (see below) tracks which fractals have hi-prec support
- Unsupported fractals show a visible warning in the GUI if user selects hi-prec on an unsupported fractal — no silent fallback

**GPU note**: GPU shaders are inherently limited to f32/f64. Adapting fixed-width software floats to run on GPU (e.g., emulated 128-bit via shader code) is a non-trivial future effort and is explicitly out of scope for this release. Tracked as a future capability in capability_table.md.

**Benefits**:
- Enables zooms to depths limited only by time and iteration count
- User has full control and visibility — no hidden mode switching
- Consistent with the project's "user decides" rendering philosophy
- Mandelbrot-first approach lets us validate the pipeline before exposing it on other fractals
