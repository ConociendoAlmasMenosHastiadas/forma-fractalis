## Overview
Version 0.2.3 refactors the project into a Cargo workspace with two crates: a pure Rust library (`forma-fractalis-core`) and GUI application (`forma-fractalis`). This enables:
- Publishing the core library to crates.io
- Using forma-fractalis as a dependency in other projects
- Headless fractal rendering without GUI dependencies
- Cleaner separation of concerns for future GPU integration (v0.2.0)
- **Automated GPU testing infrastructure** - CLI-based validation of GPU shader correctness

This release also implements **GPU test automation** to validate GPU/CPU rendering parity, catching shader bugs early and enabling regression testing.

## Dependencies
- **v0.2.0 GPU Acceleration** - Core library will contain both CPU and GPU backends
- **v0.2.1** - Pipeline improvements benefit clean library API
- **v0.2.2 Arbitrary Precision** - Core library feature, no GUI needed

//! Configuration types for fractal rendering
//!
//! These types replace the GUI-coupled state structures from app_state.rs
//! with pure data structures suitable for library use.

use crate::fractals::FractalView;
use crate::filtering::FilterType;
use scala_chromatica::ColorMap;
use std::collections::HashMap;

/// Complete configuration for rendering a fractal
#[derive(Clone, Debug)]
pub struct FractalConfig {
    /// View parameters (center, zoom, dimensions)
    pub view: FractalView,
    
    /// Maximum iterations for fractal calculation
    pub max_iterations: u32,
    
    /// Fractal-specific parameters (e.g., Julia c values)
    pub fractal_parameters: HashMap<String, f64>,
    
    /// Color mapping configuration
    pub color_config: ColorConfig,
}

/// Color mapping and modulation settings
#[derive(Clone, Debug)]
pub struct ColorConfig {
    /// The colormap to use for rendering
    pub colormap: ColorMap,
    
    /// Enable period modulation
    pub use_period: bool,
    
    /// Period value for modulo operation
    pub period: u32,
    
    /// Use custom interior color
    pub use_interior_color: bool,
    
    /// RGB color for points inside the set
    pub interior_color: [u8; 3],
    
    /// Apply logarithmic scaling
    pub use_log_scale: bool,
}

impl Default for ColorConfig {
    fn default() -> Self {
        Self {
            colormap: ColorMap::default(),
            use_period: false,
            period: 128,
            use_interior_color: false,
            interior_color: [0, 0, 0],
            use_log_scale: false,
        }
    }
}

/// Export-specific configuration
#[derive(Clone, Debug)]
pub struct ExportConfig {
    /// Scaling factor for output dimensions
    pub scale: f32,
    
    /// Supersampling factor (1 = no supersampling)
    pub supersample: u32,
    
    /// Image filtering type
    pub filter_type: FilterType,
}

impl Default for ExportConfig {
    fn default() -> Self {
        Self {
            scale: 3.0,
            supersample: 4,
            filter_type: FilterType::Lanczos3,
        }
    }
}

impl FractalConfig {
    /// Create a new configuration with default color settings
    pub fn new(view: FractalView, max_iterations: u32) -> Self {
        Self {
            view,
            max_iterations,
            fractal_parameters: HashMap::new(),
            color_config: ColorConfig::default(),
        }
    }
    
    /// Builder method: Set colormap
    pub fn with_colormap(mut self, colormap: ColorMap) -> Self {
        self.color_config.colormap = colormap;
        self
    }
    
    /// Builder method: Set fractal parameter
    pub fn with_parameter(mut self, name: impl Into<String>, value: f64) -> Self {
        self.fractal_parameters.insert(name.into(), value);
        self
    }
    
    /// Builder method: Enable period modulation
    pub fn with_period(mut self, period: u32) -> Self {
        self.color_config.use_period = true;
        self.color_config.period = period;
        self
    }
}
```

**Benefits:**
- No egui dependencies
- Builder pattern for ergonomic API
- Clear separation of rendering concerns
- Easy to serialize/deserialize for CLI usage

//! # Forma Fractalis Core - High-Performance Fractal Rendering Library
//!
//! A framework-agnostic fractal computation and rendering library supporting
//! multiple fractal types with advanced color mapping and export capabilities.
//!
//! ## Quick Start
//!
//! ```rust
//! use forma_fractalis_core::{
//!     fractals::{Mandelbrot, FractalView},
//!     config::FractalConfig,
//!     render_fractal_to_buffer,
//! };
//! use scala_chromatica::presets;
//!
//! // Create a fractal
//! let mandelbrot = Mandelbrot::new();
//!
//! // Configure view and rendering
//! let view = FractalView::new(1920, 1080);
//! let config = FractalConfig::new(view, 256)
//!     .with_colormap(presets::fire());
//!
//! // Render to buffer
//! let buffer = render_fractal_to_buffer(&mandelbrot, &config)?;
//! ```
//!
//! ## Feature Flags
//!
//! - `export` (default) - PNG export with metadata
//! - `parallel` (default) - Multi-threaded rendering with rayon
//! - `gpu` - GPU-accelerated rendering (requires v0.2.0)

// Public modules
pub mod fractals;
pub mod config;
pub mod filtering;
pub mod number_utils;

// Public re-exports for convenience
pub use fractals::{Fractal, FractalView, Parameter};
pub use config::{FractalConfig, ColorConfig, ExportConfig};

// Optionally exported modules
#[cfg(feature = "export")]
pub mod export;

// Core rendering functions (not modules, just module paths)
mod rendering;
mod rendering_pipeline;

// Public high-level rendering API
use rendering_pipeline::{render_with_config, RenderConfig, RenderTarget};

/// Render a fractal to an RGBA buffer
///
/// This is the primary rendering function for library users.
///
/// # Arguments
/// * `fractal` - The fractal implementation to render
/// * `config` - Complete rendering configuration
///
/// # Returns
/// RGBA buffer (4 bytes per pixel, row-major order)
///
/// # Example
/// ```rust
/// use forma_fractalis_core::*;
/// use forma_fractalis_core::fractals::Mandelbrot;
///
/// let mandelbrot = Mandelbrot::new();
/// let view = fractals::FractalView::new(800, 600);
/// let config = FractalConfig::new(view, 256);
///
/// let buffer = render_fractal_to_buffer(&mandelbrot, &config)?;
/// assert_eq!(buffer.len(), 800 * 600 * 4);
/// ```
pub fn render_fractal_to_buffer(
    fractal: &dyn Fractal,
    config: &FractalConfig,
) -> Result<Vec<u8>, RenderError> {
    let render_config = RenderConfig::from_fractal_config(config, fractal);
    render_with_config(&render_config, RenderTarget::Buffer)
}

/// Error type for rendering operations
#[derive(Debug)]
pub enum RenderError {
    InvalidDimensions,
    InvalidParameters(String),
    IoError(std::io::Error),
}

impl std::fmt::Display for RenderError {
    fn fmt(&self, f: &mut std::fmt::Formatter) -> std::fmt::Result {
        match self {
            RenderError::InvalidDimensions => write!(f, "Invalid render dimensions"),
            RenderError::InvalidParameters(msg) => write!(f, "Invalid parameters: {}", msg),
            RenderError::IoError(e) => write!(f, "I/O error: {}", e),
        }
    }
}

impl std::error::Error for RenderError {}
```

- Simple, focused API with single primary rendering function

- Clear error types
- Feature flags for optional functionality

#### Task 5.1: Two-Phase Public API (FractalIterations)
**Motivation**: The GUI needs to skip recomputing iterations when only colors change (colormap drag, period, log scale). Future animation features — e.g., "rolling" colors across a frozen fractal — need the same separation: compute once, recolor many times. This also enables CLI animation loops without re-rendering the fractal per frame.

**Design: `FractalIterations` type**

New public type in `core/src/lib.rs` (or `core/src/rendering.rs`):

```rust
/// Pre-computed iteration counts for a fractal view.
///
/// Produced by `compute_fractal_iterations()`. Can be reused with
/// different `ColorConfig` values to recolor without recomputing.
pub struct FractalIterations {
    /// Raw escape counts, one per pixel, row-major
    pub data: Vec<u32>,
    pub width: u32,
    pub height: u32,
    pub max_iterations: u32,
    // Metadata for cache validity checks
    pub center_x: f64,
    pub center_y: f64,
    pub zoom: f64,
    pub fractal_parameters: HashMap<String, f64>,
}

impl FractalIterations {
    /// True if this cache is still valid for the given config.
    /// Checks view geometry, max_iterations, and fractal params.
    pub fn is_valid_for(&self, config: &FractalConfig) -> bool {
        self.width == config.view.width
            && self.height == config.view.height
            && self.max_iterations == config.max_iterations
            && self.center_x == config.view.center_x
            && self.center_y == config.view.center_y
            && self.zoom == config.view.zoom
            && self.fractal_parameters == config.fractal_parameters
    }
}
```

}

#### Task 5.2: Color Offset for Animation

**Motivation**: "Rolling" colors means advancing the colormap lookup index each frame without touching the fractal geometry. A `color_offset: u32` added to the iteration count before colormap lookup produces this effect when period modulation is active (`effective_iter = (iter + offset) % period`).

**Changes to `ColorConfig`:**
```rust
pub struct ColorConfig {
    // ... existing fields ...
    
    /// Offset added to iteration count before colormap lookup.
    /// Used for color animation. Effective only when use_period = true.
    /// Each increment by 1 shifts the colormap by one period step.
    pub color_offset: u32,
}
```

Default is `0`. Builder method:
```rust
pub fn with_color_offset(mut self, offset: u32) -> Self {
    self.color_offset = offset;
    self
}
```

**Changes to `apply_colors_from_cache()` in `rendering.rs`:**
```rust
// Before:
color_from_iterations(iter, max_iterations, colormap, use_period, period, ...)

// After:
let shifted_iter = if use_period && period > 0 {
    iter.wrapping_add(color_offset) % period
} else {
    iter
};
color_from_iterations(shifted_iter, max_iterations, colormap, use_period, period, ...)
```

Wait — `color_from_iterations` handles the period modulo internally. The offset needs to be applied to the value passed in OR added as a phase to the colormap lookup. The cleanest approach: pass `color_offset` through to `apply_colors_from_cache()` as an additional parameter and add it before the lookup. Check scala-chromatica's `color_from_iterations` signature to see if offset can be passed directly; if not, apply it to `iter` before calling.

**Checklist:**

## Migration Guide (for v0.2.2 → v0.2.3 users)

### Breaking Changes

**Import Path Changes:**
```rust
// Old (v0.2.2)
use forma_fractalis::fractals::Mandelbrot;
use forma_fractalis::rendering;

// New (v0.2.3) - GUI application
use forma_fractalis::fractals::Mandelbrot;  // Re-exported from core

// New (v0.2.3) - Library users
use forma_fractalis_core::fractals::Mandelbrot;
use forma_fractalis_core::render_fractal_to_buffer;
```

**Configuration Changes:**
```rust
// Old (v0.2.2) - Many individual parameters
rendering::render_fractal(
    frame, view, colormap, max_iterations,
    use_period, period, use_interior_color, interior_color,
    use_log_scale, &fractal, &fractal_parameters
);

// New (v0.2.3) - Configuration object
let config = FractalConfig::new(view.clone(), max_iterations)
    .with_colormap(colormap.clone())
    .with_period(period);

let buffer = render_fractal_to_buffer(&fractal, &config)?;
```

**Build Command Changes:**
```powershell
# Old (v0.2.2)
cargo build --release

# New (v0.2.3) - Build both
cargo build --release

# New (v0.2.3) - Build only GUI
cargo build --release -p forma-fractalis

# New (v0.2.3) - Build only library
cargo build --release -p forma-fractalis-core
```

## Alternative Approach: Feature Flags (Not Recommended)

[features]

```

**Pros:**

- Easier versioning

**Cons:**

- Optional dependencies still downloaded by default
- More complex feature matrix to test
