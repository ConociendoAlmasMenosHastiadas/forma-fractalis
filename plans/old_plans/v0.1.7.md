## Refactoring Work (CRITICAL - Do First)

### Problem Analysis

**Issue**: The v0.1.6 implementation has significant code duplication:

1. **Manual Field-by-Field Conversion**: The `load_from_metadata()` method in main.rs manually maps 20+ fields from `FractalMetadata` to various state structs (ViewState, InputState, ColorState, etc.). This is error-prone and hard to maintain.

2. **String Conversion Everywhere**: Fields like iterations, dimensions, and parameters are converted to strings for InputState, then parsed back to numbers for rendering. This round-trip is wasteful.

3. **No Bidirectional Conversion**: We can convert metadata → app state, but we can't easily go app state → metadata. This means `create_png_metadata()` in export.rs takes 13 parameters instead of state structs.

4. **Duplication with CLI**: The planned CLI rendering would need to duplicate the state construction logic, or we'd need to refactor anyway.

### Refactoring Plan

**Goal**: Create clean, bidirectional conversion between `FractalMetadata` and grouped state structs.

```rust
fn render_from_cli(args: &CliArgs) -> Result<(), String> {
    // Load metadata
    let metadata = if args.input.ends_with(".png") {
        load_png_metadata(&args.input)?
    } else {
        load_json_metadata(&args.input)?
    };
    
    // Convert to state structs (uses Phase 1 From implementations)
    let mut fractal_state = FractalState::from(&metadata);
    let mut view_state = ViewState::from(&metadata);
    let mut color_state = ColorState::from(&metadata);
    let mut input_state = InputState::from(&metadata);
    let mut export_state = ExportState::from(&metadata);
    
    // Apply CLI overrides
    if let Some(width) = args.width {
        view_state.view.width = width;
        input_state.width = width.to_string();
    }
    if let Some(iterations) = args.iterations {
        input_state.iterations = iterations.to_string();
    }
    // ... more overrides
    
    // Render (uses Phase 2 refactored export function)
    export_png_from_state(
        &fractal_state,
        &view_state,
        &color_state,
        &input_state,
        &export_state,
    )?;
    
    Ok(())
}
```

## Architecture Notes

### Integration with v0.1.5/v0.1.6 Improvements

The CLI rendering leverages several architectural improvements:

1. **Grouped State Pattern (v0.1.5):**
   - CLI can construct state structs directly
   - No need to replicate complex initialization logic
   - Easy to validate state before rendering

2. **Metadata Parsing (v0.1.6):**
   - Reuse PNG metadata parser for CLI input
   - Consistent deserialization logic
   - Same validation rules apply

3. **Headless Rendering:**
   - Rendering pipeline already separate from GUI
   - Just need entry point that doesn't initialize egui
   - State structs make this clean

**Example CLI Architecture:**
```rust
// CLI entry point
fn main_cli(args: CliArgs) -> Result<()> {
    // Load metadata from PNG or JSON
    let metadata = load_metadata(&args.input)?;
    
    // Construct state structs (reusing v0.1.5 patterns)
    let fractal_state = metadata.into_fractal_state();
    let view_state = metadata.into_view_state();
    let color_state = metadata.into_color_state();
    let export_state = metadata.into_export_state();
    
    // Override with CLI args if provided
    if let Some(width) = args.width {
        export_state.width = width;
    }
    // ... more overrides
    
    // Render (no GUI needed)
    let image = render_fractal(
        &fractal_state,
        &view_state,
        &color_state,
        &export_state,
    )?;
    
    // Save
    save_png(&args.output, &image, &metadata)?;
    
    Ok(())
}
```
