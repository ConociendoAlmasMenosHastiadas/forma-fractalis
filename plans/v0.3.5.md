## Feature: View Coordinate Transformations

### Transformation Parameters

Add to `FractalView` (or new `TransformState`):
```rust
pub struct ViewTransform {
    /// Rotation angle in degrees (0-360)
    pub rotation: f64,
    /// Flip across real axis (horizontal flip of imaginary values)
    pub flip_imag: bool,
    /// Flip across imaginary axis (horizontal flip of real values)
    pub flip_real: bool,
}
```

### Mathematical Model

The transformation is applied in `screen_to_complex()` AFTER computing raw coordinates:

```rust
fn screen_to_complex_transformed(&self, x: u32, y: u32) -> (f64, f64) {
    // 1. Get raw complex coordinates (current implementation)
    let (mut real, mut imag) = self.screen_to_complex_raw(x, y);
    
    // 2. Translate to origin-relative coordinates
    let rel_real = real - self.center_x;
    let rel_imag = imag - self.center_y;
    
    // 3. Apply rotation (if non-zero)
    let (rot_real, rot_imag) = if self.transform.rotation != 0.0 {
        let theta = self.transform.rotation.to_radians();
        let cos_t = theta.cos();
        let sin_t = theta.sin();
        (
            rel_real * cos_t - rel_imag * sin_t,
            rel_real * sin_t + rel_imag * cos_t
        )
    } else {
        (rel_real, rel_imag)
    };
    
    // 4. Apply axis flips
    let flip_real = if self.transform.flip_real { -rot_real } else { rot_real };
    let flip_imag = if self.transform.flip_imag { -rot_imag } else { rot_imag };
    
    // 5. Translate back
    (self.center_x + flip_real, self.center_y + flip_imag)
}
```

### Edge Cases & Considerations

1. **Mouse interaction with transforms**: When user clicks to zoom, the click point must be transformed correctly to find the target complex coordinate

2. **Panning direction**: Pan should move in screen-space, not transformed space, for intuitive UX

3. **Rotation center**: Rotation is around the current view center, not the origin

4. **Combination order**: Apply rotation first, then flips (consistent behavior)

5. **Performance**: Sin/cos computation per pixel is expensive; consider:
   - Precompute sin/cos once per frame
   - Pass as uniforms to GPU
   - Bake into 2x2 transformation matrix

### Optimized Implementation

Use a 2x2 transformation matrix computed once:
```rust
fn compute_transform_matrix(&self) -> [[f64; 2]; 2] {
    let theta = self.transform.rotation.to_radians();
    let cos_t = theta.cos();
    let sin_t = theta.sin();
    
    // Rotation matrix
    let mut m = [[cos_t, -sin_t], [sin_t, cos_t]];
    
    // Apply flips
    if self.transform.flip_real {
        m[0][0] = -m[0][0];
        m[1][0] = -m[1][0];
    }
    if self.transform.flip_imag {
        m[0][1] = -m[0][1];
        m[1][1] = -m[1][1];
    }
    
    m
}
```
