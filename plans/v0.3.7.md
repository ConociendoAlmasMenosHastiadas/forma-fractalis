# Plan v0.3.7 - Distribution: crates.io Publication & Code Signing

**Fractal**: TBD - to be determined before release finalization

## Overview

This plan covers two "going public" concerns that are best tackled together:
1. Publishing `forma-fractalis-core` to crates.io (library discoverability)
2. Code-signing the Windows binary (removes the SmartScreen "unknown publisher" warning)

Both require one-time setup work and have no algorithmic dependencies on fractal development.
They are grouped here because they share the theme of making the project trustworthy to strangers.

## Part 1: Windows Code Signing

### Background
Windows SmartScreen assigns a "reputation score" to every downloaded executable. An
unsigned binary starts with zero reputation and triggers "Windows protected your PC".
Code signing with a trusted certificate removes this warning. For open-source projects
there are two realistic paths.

---

### Path A: SignPath.io (Recommended for open source)

[SignPath.io](https://signpath.io) is a code-signing service that provides **free code
signing for open-source projects** — including EV-level certificates. It is the cleanest
path for a project like this.

**Requirements to qualify:**
- The project must be publicly hosted (GitHub satisfies this).
- Builds must be reproducible and triggered from source via CI, not from local machines.
- The SignPath Foundation reviews the application; approval typically takes 1-2 weeks.

**Setup steps:**
1. Apply for the Open Source program at https://signpath.io/product/open-source
2. Connect the GitHub repository to SignPath (OAuth app installation).
3. Add a `signing-policy.yml` to the repository root describing what artifacts to sign.
4. Update the GitHub Actions / CI workflow to submit the build artifact to SignPath after
   `cargo build --release`. SignPath signs it and returns the signed binary.
5. Alternatively: if no CI exists yet, set up a minimal GitHub Actions workflow just for
   signing the release zip. The workflow needs to produce `forma-fractalis.exe` as an
   artifact, then call the SignPath action.

**What you get:**
- A signed `.exe` with "Forma Fractalis" (or your chosen publisher name) shown in
  Windows security dialogs.
- EV-level reputation: SmartScreen warning disappears immediately on first download —
  no reputation build-up period needed.
- Free, renewable annually as long as the project remains open source.

**Prerequisite: CI pipeline.** SignPath requires the binary to come from a CI build, not
a local `cargo build`. If the project does not yet have GitHub Actions, a minimal workflow
must be added before this step can complete.

---

### Path B: Purchase a commercial OV certificate (No CI required)

If CI is not desired, a standard Organisation Validation (OV) certificate can be used
with the local build + `signtool.exe` signing workflow already in `build_scripts/`.

**Cost:** ~$70–200/year from providers like Sectigo, DigiCert, GlobalSign.

**Note on EV certificates:** EV certificates give instant SmartScreen reputation (same
as SignPath), but since ~2023 EV certificates are only issued on hardware tokens (USB
HSM). Cloud-based EV signing is available via SignPath or Azure Trusted Signing (see
below) — not directly from a USB token in a CI environment without extra tooling.

**OV certificate process:**
1. Purchase a certificate from a CA (Sectigo is the most common for indie devs).
2. Generate a CSR and complete identity validation (they will verify name/address via
   documents — takes 1-3 business days).
3. Install the certificate in the Windows Certificate Store on your build machine.
4. Sign the binary after build:
   ```powershell
   signtool sign /a /fd SHA256 /tr http://timestamp.sectigo.com /td SHA256 `
       "builds\forma-fractalis.exe"
   ```
5. Verify: `signtool verify /pa builds\forma-fractalis.exe`
6. Update `build_scripts/windows-build.ps1` to run the signing step automatically.

**What you get:** Publisher name shown in SmartScreen/UAC prompts. Reputation still
builds over time with an OV cert (not instant like EV/SignPath). After enough downloads
without AV flags, SmartScreen stops showing the warning at all.

---

### Path C: Azure Trusted Signing (Microsoft-native, subscription)

Microsoft offers [Azure Trusted Signing](https://azure.microsoft.com/en-us/products/trusted-signing)
with SmartScreen integration at ~$9.99/month. It uses cloud HSM storage so no USB token
is needed. Worth considering if Azure is already in use, otherwise SignPath is simpler for
open source.

---

### Recommended decision tree

```
Is the project willing to set up GitHub Actions?
  YES -> Use SignPath.io (free, EV-equivalent, no cert cost)
  NO  -> Is a recurring cert cost acceptable?
           YES -> Purchase OV cert from Sectigo (signtool.exe local signing)
           NO  -> Document "More info -> Run anyway" workaround and revisit later
```

## Part 2: crates.io Publication

### The Question

Should `forma-fractalis-core` be published to crates.io at all?

Arguments for:
- Discoverability among Rust developers searching for fractal/rendering libraries
- Signals project maturity and commitment to a stable public API
- `batch_export.rs` and `simple_render.rs` examples become genuinely runnable for others

Arguments against:
- Once published, versions cannot be yanked cleanly — semver stability is expected
- Attracts library-API issues and questions that are different from the tool's user base
- Doesn't directly serve the donor/user audience; those people find the tool via GitHub,
  Reddit, or search — not crates.io
- Maintenance overhead increases

### If the Decision is Yes (Publish)

- [ ] Audit the public API surface of `forma-fractalis-core` — decide what is truly public
      vs implementation detail; use `pub(crate)` aggressively to reduce the exposed surface
- [ ] Set keywords in core/Cargo.toml: `fractal`, `mandelbrot`, `rendering`, `gpu`, `generative`
- [ ] Write a one-sentence crate description that is useful to someone browsing crates.io
- [ ] Ensure all public items have at least a one-line doc comment
- [ ] `cargo publish --dry-run` to catch any missing fields
- [ ] Publish `forma-fractalis-core` first, then `forma-fractalis` (GUI binary)

### If the Decision is No (Skip crates.io)

- [ ] Add a note to README.md that the library is available from source only
- [ ] Close this plan as intentionally skipped

## Mothballed from v0.2.5: Adjusted Probability Julia

Originally implemented in v0.2.5 (commit context: April 2026). All infrastructure is in place
but the visual output was wrong and the reference documentation was too ambiguous to resolve
confidently. The fractal is hidden from the UI and its tests are marked `#[ignore]`.

### What was implemented (v0.2.5)
- `core/src/fractals/adj_prob_julia.rs` -- orbit accumulation, per-pixel z_0
- `FractalType::AdjProbJulia` variant registered (enum, as_str, create_instance, parse_fractal_type)
- InputState fields in `gui/src/app_state.rs`: threshold, samples, burn_in, seed, use_log_density
- FractalGUI impl in `gui/src/fractal_gui.rs` (5 controls, no z_0 sliders -- z_0 = screen pixel)
- Wired into `gui/src/main.rs` and `gui/src/cli.rs`

### Formula as implemented
```
z_{n+1} = s * sqrt(z_n - z_0)    where z_0 = complex coordinate of the current pixel

s = -1 if uniform_random(0,1) < R  (threshold R)
s = +1 otherwise

sqrt is the principal complex sqrt: mag = sqrt(|w|), arg = arg(w)/2
```

### What needs investigation before un-mothballing
- Verify the formula against a reliable reference -- the original source had a typo
  (used `arg(z_n)/2` instead of `arg(z_n - z_0)/2`; the code uses the corrected form
  but the expected image is unknown)
- Check whether the iteration should start from `z = z_0` rather than `z = 0`
- Check whether the random sign should be per-orbit vs per-step
- Possibly compare against a known implementation of "random iterated function system"
  IFS Julia sets for the `z -> sqrt(z - c)` family
- The burn-in and samples defaults (10 and 20) may be too low to produce a visible image;
  try larger values (burn_in=50, samples=200+) when debugging

3. Add `FractalType::AdjProbJulia` back to `FractalType::all()` in `core/src/fractals/mod.rs`
